# Security Policy

## Supported Versions

VETA Trading Platform is under active development. Security fixes are provided for the latest commit on the default branch only, unless a maintained release branch is explicitly documented.

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues.

If you believe you have found a vulnerability, use GitHub's private vulnerability reporting feature from the repository Security tab.

If private vulnerability reporting is unavailable, open a public issue only to request a preferred private security contact. Do not include exploit details, credentials, logs, tokens, or reproduction steps.

Useful reports include:

- A clear description of the issue
- Affected component, endpoint, package, or workflow
- Steps to reproduce, where safe to share privately
- Potential impact
- Any relevant logs, screenshots, or proof of concept
- Suggested mitigation, if known

Examples of security issues include authentication or authorization bypasses, account or portfolio data exposure, trade/order manipulation, secret leakage, injection flaws, XSS, CSRF, SSRF, remote code execution, dependency supply-chain vulnerabilities, and unsafe handling of broker/API credentials.

## Response Expectations

We aim to acknowledge valid private reports within 7 days.

After triage, we will let you know whether the report is accepted, needs more information, or is out of scope. If accepted, we will coordinate a fix and disclosure timeline before public details are shared.

## Responsible Disclosure

Please give us reasonable time to investigate and remediate before disclosing the issue publicly. We appreciate good-faith research and will credit reporters in release notes or advisories when appropriate, unless anonymity is requested.

## Public Issues

Public GitHub issues are welcome for non-sensitive bugs, hardening suggestions, documentation gaps, and general security questions. Do not include vulnerability details in public issues until a fix is available.
