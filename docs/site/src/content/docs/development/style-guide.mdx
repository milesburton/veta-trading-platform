This page documents the design tokens. For live, interactive UI primitives (buttons, menus, status dots), see the [component kitchen sink](../components/) instead. This page is about colour, type, and spacing; that one is about components built from them.

Everything here is sourced from CSS custom properties, not hardcoded per-component. If a new panel needs a colour, it should reference one of these tokens rather than picking a fresh hex value.

## Gray scale

Eleven steps, each with a documented purpose and contrast ratio against the page background. Tailwind exposes these under purpose-named aliases (`text-primary`, `bg-panel`, `border-divider`, etc.) rather than numbered ones, so a change to the palette doesn't require renaming every usage.

`--gray-600` is deliberately below AA contrast. It marks disabled or purely decorative content, never a value a trader needs to read.

## Typography

The platform uses a single monospace stack everywhere. Trading UIs are dense with tabular figures (prices, quantities, P&L), and monospace keeps columns of numbers aligned without extra formatting work.

```css
font-family: "JetBrains Mono", "Fira Code", "Cascadia Code", monospace;
```

<Source path="frontend/tailwind.config.cjs" label="tailwind.config.cjs" />

There is no separate type scale beyond Tailwind's defaults (`text-xs` through `text-2xl`). The density comes from font choice and the gray-scale hierarchy above, not from a large heading scale. Most panel body text sits at `text-xs`/`text-sm`; reserve anything larger for a panel's own title bar.

## Theme variants

Four `data-theme` values exist: the default (dark), plus `darker`, `light`, and `high-contrast`. Every token above is redefined per theme in `frontend/src/index.css`. Components should read tokens rather than assume the default dark values, since a component that hardcodes an RGB triplet breaks the other three themes silently.

## Using tokens in code

**Tailwind classes** (preferred for anything styled in JSX):

```tsx
<div className="bg-panel border border-divider text-primary">
  <span className="text-semantic-up">+2.4%</span>
</div>
```

**Raw values** (Recharts, canvas, inline SVG `fill=`, anything that needs a real string at runtime):

```tsx
import { COLOR } from "../tokens";

<Line stroke={COLOR.UP} />
```

`COLOR` reads the live CSS variable on each access, so it follows theme switches without a re-render trigger of its own. Never cache a `COLOR.*` value in a module-level constant.

## Docs site tokens

The Astro docs site (this site) mirrors the frontend's gray scale and semantic palette in `docs/site/src/styles/custom.css`, explicitly kept in sync with `frontend/src/index.css` by comment convention. If you change one, change the other. The docs site additionally maps `--semantic-cross` onto Starlight's own `--sl-color-accent*` variables, and uses Starlight's built-in `--sl-color-purple*` for anything that isn't trading-specific (asides, the [status page](/veta-trading-platform/status/) backdrop).
