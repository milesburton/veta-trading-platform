VETA runs the entire platform inside a Docker-based Dev Container so every developer starts with the same environment. Every change goes through automated testing at four levels before it can reach production.

## Dockerised development

The repository ships a `.devcontainer/devcontainer.json` that configures VS Code (or JetBrains) to build and run the full platform inside a container. This includes:

- **Deno 2.7** for all backend services
- **Node 24** for the React frontend
- **PostgreSQL 16** for journal, user, and replay data
- **Redpanda** (Kafka-compatible) for the message bus
- **Supervisord** managing the trading microservices (more than 40 programs), with Postgres and Redpanda run through Docker Compose

When you open the repository in VS Code and accept "Reopen in Container", you get a functional trading platform with zero local setup. The MOTD shows available commands.

```sh
supervisorctl status          # see all services
cd frontend && npm run dev    # start the frontend
```

## Test pyramid

The project enforces testing at four levels, each catching different classes of bugs:

### Unit tests (fast, isolated)

- **Backend**: {testInventory.backend.unit.cases} tests across {testInventory.backend.unit.files} files via `deno task test`. Pure function tests for OMS validation, algo slicing, FIX parsing, analytics maths, grid filtering.
- **Frontend**: {testInventory.frontend.unit.cases} tests across {testInventory.frontend.unit.files} files via Vitest. Redux slices, React components, panel registry, layout models, ticket resolution rules, hooks.
- **Coverage**: v8 provider via Vitest; backend via Deno `--coverage`. Coverage badge auto-updated on every push to main.

See [Testing](/veta-trading-platform/development/testing/) for the full breakdown and current counts.

### Integration tests (services + database)

- {testInventory.backend.integration.files} test files ({testInventory.backend.integration.cases} cases) run against the full service stack with PostgreSQL and Redpanda; a further {testInventory.backend.testcontainers.files} files ({testInventory.backend.testcontainers.cases} cases) run the same suites via testcontainers.
- Test real order flow: submit via WebSocket, OMS validates, algo routes, EMS fills, journal persists.
- Each algo strategy verified: LIMIT, TWAP, POV, VWAP, ICEBERG, SNIPER, ARRIVAL_PRICE, IS, MOMENTUM.
- Intelligence pipeline: feature engine, signal engine, recommendation engine.
- Journal and market-data HTTP contract tests.

### E2E tests (browser automation)

- {testInventory.frontend.playwright.files} Playwright spec files running headless Chromium against the Vite dev server.
- GatewayMock intercepts WebSocket and HTTP to test frontend behaviour without real services.
- Auth flows, order submission, market data rendering, fixed income panels, algo order lifecycle, session replay, observability layouts.
- Page object pattern: `AppPage`, `OrderTicketPage`, `OrderBlotterPage`, `MarketLadderPage`.

### Smoke tests (production-like)

- {testInventory.frontend.gateSmoke.cases} end-user-flow assertions gate every deploy; the backend testcontainers smoke suite (`smoke.full.tc.test.ts`) covers 65 end-to-end checks against an ephemeral stack in CI.
- Health checks for all backend services.
- Full OAuth login flow with browser-style headers.
- Order lifecycle: submit, then fill or expire within timeout.
- Auth edge cases: unknown user, wrong or missing password, disabled public registration, invalid token, and role checks on admin-only endpoints.
- Each of the nine algo strategies reaches a terminal or acknowledged state.
- Downstream services (news, recommendation, feature, signal, scenario, RFQ, dark pool, CCP) report valid health and stats shapes.
- Disk usage assertion: the gateway `/system` endpoint reports disk usage and it is not exhausted.

## Pre-commit hooks

The pre-commit hook runs 16 steps. You cannot commit until all pass:

1. Clean working directory check
2. `deno lint`: backend linting
3. `deno task check`: backend type-checking
4. `deno task test`: backend unit tests
5. Frontend linting and formatting (Oxlint, Oxfmt)
6. Frontend type-checking (`tsc --noEmit`)
7. Frontend unit tests (Vitest)
8. Integration tests (if services are running locally)
9. Migration safety, Prometheus alert rules, docs drift, private IP and network detail scans, docs validation, Fallow audit, and secret file checks

See [Contributing](/veta-trading-platform/development/contributing/#pre-commit-hooks) for the full ordered list.

## Code conventions

- **TypeScript everywhere**: Deno for backend, Vite + React for frontend
- **No comments**: code should be self-documenting
- **Functional where possible**: pure functions over mutable module state
- **Single source of truth**: shared types in `@veta/types/*`, shared utilities in `@veta/*`
- **Import map aliases**: `@veta/http` not `../lib/http.ts`
- **Conventional commits**: `feat(risk):`, `fix(ci):`, `refactor:`, `docs:`
